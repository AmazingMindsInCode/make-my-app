# 经验日志规范 · 使用留痕，反哺插件进化

「我要做软件」插件的使用过程本身就是宝贵的反馈数据。所有失败、教训、新坑、用户纠正都要**当场**记入项目的 `.make-my-app/experience-log.md`，用户可随时 `/export` 汇总导出发给插件开发团队。**记录是义务，不是可选动作。**

## 一、记录什么（六类事件，触发即记）

| 类型 | 触发时机（谁负责记） |
|---|---|
| failure 失败 | 任务连续 2 轮修复仍 fail / spec 测试 blocked / 构建失败超过 10 分钟（mma-build、mma-spec-tester 回报后由主流程记） |
| lesson 教训 | 任何"早知道就少走弯路"的发现：方案选错、任务拆分不当、spec 写得太虚（各 skill 自省时记） |
| pitfall 新坑 | 踩到 pitfalls.md 没有的坑（解决后同时追加 pitfalls.md，两处联动）（所有 skill） |
| correction 用户纠正 | 用户指出 AI 理解错了/做错了（"我说的不是这个意思"）——记原话与纠正后理解（所有 skill） |
| install 代办安装结果 | 代办安装成功/失败及原因（mma-env） |
| suggestion 改进建议 | 用户主动提的"要是能…就好了"（所有 skill） |

## 二、条目格式（追加到 `.make-my-app/experience-log.md`，按时间正序）

```markdown
## E7 | failure | 2026-09-30 14:20
- 阶段：build ｜ 任务：T3（统计图表）
- 事件：图表库在无网络环境构建失败，连续 2 轮未解决
- 根因：vite 构建时需在线拉取字体图标，用户网络受限
- 处置：改用纯 CSS 柱状图绕过，已解决
- 建议：黄金路径图表方案应提供离线降级选项
```

规则：
- 每条必须有"事件/根因/处置"三要素；根因没查清就写"未查明 + 推测"。
- 一事一条，不合并；用用户原话记 correction。
- **隐私红线：绝不记录**密码、密钥、手机号、身份证号、银行卡号、真实姓名住址。涉及路径时只记相对路径。
- 文件不存在时按 `templates/experience-log.md` 建头再追加。

## 三、导出（/export，mma-export 技能负责）

1. 校验日志存在且有内容；统计各类型/各阶段条数。
2. 汇总生成 `.make-my-app/export/experience-report-YYYYMMDD.md`：项目概况（应用名、走过的阶段、任务完成率、插件版本）+ 统计 + 全部条目明细。
3. **脱敏扫描**（导出前必做）：正则扫常见敏感模式（密码赋值行、长数字串、邮箱手机号），命中即打码为 `***` 并在报告头注明"已自动脱敏 N 处"。
4. 告诉用户文件在哪、一句话"发给插件团队即可帮助它变好"。
