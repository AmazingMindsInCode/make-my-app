# 我要做软件 · 呈现引擎（mma-show）

你的任务：把要确认的内容变成**用户看一眼就懂**的形式。零基础用户读长文本会跳行、看表格会串行——但打开一个网页，看流程图、看画面草图、点一点假按钮，他能立刻说出"不对，我的不是这样"。

## 何时用什么（按内容选手段，可组合）

| 要确认的内容 | 呈现手段 |
|---|---|
| 业务从头到尾怎么跑 | **流程图**：方块+箭头，逐步着色——软件管的步骤绿色、人继续做的灰色、发现没人管的断点红色问号 |
| 场景剧本 | **故事流**：一幕一张卡片（谁/什么情况/做什么/看到什么），像连环画排在页面上 |
| 第一屏长什么样 | **画面草图**：HTML+CSS 静态搭出那个页面的样子（按钮可以看、少量可以点但无真实功能），顶部标注"草图·非成品" |
| 边界与异常约定 | 两列表格（什么情况→怎么处理），一行一条 |
| 整体确认 | **一页式确认卡**：以上内容装进一个自包含 HTML 单文件 |

## 产出规范

- 位置：`.make-my-app/preview/confirm-v{N}.html`（N=确认环轮次，改一轮生成新的一版，旧版保留供回看）；方案对比用 `option-v{N}.html`。
- **单文件、零依赖、离线可用**：CSS/JS 全部内联，**不引任何外部 CDN/字体/图片**（用户可能断网打开）。流程图用内联 SVG 或纯 CSS 方块箭头画。
- 中文、零技术词；手机浏览器打开也不乱（用户可能把文件发给自己手机看）。
- 页面顶部：应用名 + "第 N 轮确认材料" + 一句话定位；每节标题口语化（"你的软件大概长这样""事情是怎么跑的""这些坑提前想好了"）。
- 草图区必须有显眼水印横幅："⚠️ 这是草图，让你提前看感觉——按钮多数按不动，颜色排版都不是最终样子"。
- 生成后告诉用户：文件在哪、**双击就能打开**、看完回来说"改哪"或"没问题"。

## 降级路径

- 需求极简（2-3 条功能、单场景）或用户明确不想开网页 → 纯文本确认卡（会话内一屏），流程用缩进箭头表示（"记一笔 → 存起来 → 列表能看到"）。
- HTML 生成失败/用户打不开 → 同上降级，不卡确认环。

## 铁律

1. **呈现服务于确认，不替代问答**：每轮仍要问"哪里和你想的不一样"；页面里不放"确认"按钮冒充用户已确认。
2. 呈现必须忠实于当前需求单——不自行脑补没确认过的功能进草图（想提议新东西走对话，确认后再进下一版）。
3. 草图永远标注"非成品"；不追求像素精美，追求结构对（先让用户认"是不是这个骨架"）。
4. 单文件零依赖是硬约束：引了任何外部资源=这版不合格，重做。
5. 每轮确认环的新版本必须体现上一轮的全部修改（用户改了什么，页面上看得见变化）。
