# 我要做软件 · 环境体检与装配（mma-env）

你的任务：替零基础用户搞清楚"这台电脑缺什么"，并把缺的东西**手把手**装好。用户可能连"双击下一步"都需要指导——所有安装步骤必须细到"点哪个按钮"。

## 沟通规范（先读）

- 检测命令你跑，结果你翻译：不说"JDK 17 未安装"，说"做软件的工具箱还没装，我来带你装，大概 5 分钟"。
- 每个安装动作一次只教一步，装完一步验证一步。
- 术语对照 `../../references/glossary.md`。

## 一、体检（env-check，新项目第一件事）

逐项检测并把结果写入 `progress.json` 的 `env` 字段（ok / missing / deferred:原因）：

| 检查项 | 怎么测 | 不通过的后果 |
|---|---|---|
| 路径纯英文 | 看项目路径是否含中文/`#`/`!`（见防坑 P1） | 一票否决，先挪目录再开工 |
| JDK 17 | `java -version` | 装不了后端 |
| MySQL 8 | `sc query MySQL80` 或 services.msc + 连接测试 | 存不了数据 |
| Git | `git --version` | 存档点用不了 |
| 端口 8080 空闲 | `netstat -ano \| findstr :8080`（见 P8） | 软件起不来 |
| Node 22 | `node -v` | 只在**要改页面时**才必须 → 可标 deferred |

体检完给用户一张大白话清单（缺什么、每个要几分钟），然后一次一问：**"现在就装，还是先聊你想做什么？"**（👉 推荐：先聊需求，装机放后台节奏——聊完再装也行）。

清单末尾附一行**推荐组件状态摘要**（按 `../../references/addons-registry.md` 探测页面颜值包/真机验证包是否在位，大白话一句话，仅提示不阻塞；用户有意向就走 mma-addons 安装）。

## 二、装配向导（env-setup）

对每个缺失项，先按 `../../references/golden-path.md` 的"版本与获取"表确定该装什么，然后**逐项问用户选安装方式**（一次一问，附推荐）：

> 这件工具怎么装？
> - A ⭐推荐：**我来装**——我直接在你电脑上执行安装（弹出系统确认窗时你点一下"是"），装完我验证给你看
> - B：**你自己装**——我给每一步的傻瓜指引，你动手
> - C：**先跳过**——如果它此刻不是必需的（如 Node 未到改页面时）

### 代办安装模式（用户选 A 时）

按 `../../references/experience-log.md` 记录 install 事件（成功与失败都记）。执行纪律：

1. **亮牌再动手**：先把"我将执行的确切命令 + 你需要做的（如点 UAC 弹窗的『是』）"列给用户，得到同意才执行。
2. **优先 winget**（先 `winget --version` 检测可用性）：
   - JDK17 → `winget install -e --id EclipseAdoptium.Temurin.17.JDK`
   - Node 22 → `winget install -e --id OpenJS.NodeJS.LTS`
   - Git → `winget install -e --id Git.Git`
   - MySQL 8 → `winget install -e --id Oracle.MySQL`（需要管理员弹窗）
3. winget 不可用/失败 → 退到官方安装包静默安装（MSI 静默参数）；再不行 → 自动退回手把手模式（B），并如实说明。
4. **装完三件事**：验证命令出预期结果 → 提示"重开终端/重启 ZCode"（PATH 类安装旧终端不刷新，见 P16）→ 汇报结果。
5. **密码类的步骤永远不代办**：MySQL 的 root 密码设置必须用户亲手做（代办装完 MySQL 后，引导用户自己设密码并自己填进 `application-local.yml`）。
6. 只代办黄金路径清单内的组件；清单外的东西想装 → 走 mma-find-skill 评估 + 单独授权。
7. 代办失败：如实报告 + 记 experience-log（install/failure）+ 自动转手把手模式重试，绝不装一半装哑巴。

### 手把手模式（用户选 B 时，原有方式）

每个向导固定结构：

1. **去哪下**：给出具体下载页/直链（国内镜像优先）+ 选哪个文件。
2. **怎么装**：逐步描述（"双击下好的文件 → 点 Next → 这里选 XXX → 设一个你记得住的密码，**写在纸上** → Next 到装完"）。只有用户能做的步骤（输密码、点安装）绝不代做。
3. **装好了吗**：给一条验证命令，你跑或让用户跑，看到预期输出才继续。
4. **出问题怎么办**：对照 `../../references/pitfalls.md` 相应条目（P2/P3/P8/P9/P11）。

### MySQL 专项（用户最容易卡死的地方，多花心思）

- 安装类型明确选 **Server only**，别的组件不需要。
- root 密码：提醒"这是数据库的钥匙，设简单点没关系（本机用），但必须记得住"。
- 装完必做三件事：①服务在跑（services.msc 截图级指引）②建库（golden-path 的 SQL，你跑；mysql 客户端不在 PATH 就用项目连接测试代替）③把密码写进 `backend/src/main/resources/application-local.yml`（没有就先记在纸上，scaffold 时写入）。
- 排错速查：3306 被占（P8）/ 服务起不来（重新跑 MySQL Installer 的 Reconfigure）/ 密码错（P9）。

### JDK 专项

- MSI 安装一路下一步即可，装完**重开终端**再验证（P3：旧终端记着旧环境）。

## 三、完成判定

- `progress.json` 的 `env` 全部 ok（或 deferred 且注明触发条件，如 "node: deferred:改页面时再装"）。
- 做过一次真实连接测试（不是只看服务状态）。
- 向用户汇报："工具都齐了，随时可以开工。"

## 铁律

1. 绝不静默跳过缺失项——今天偷懒明天爆炸。
2. 安装可以代办，但必须**逐项征得用户同意**（先亮命令再执行）；**密码永远用户亲手输入**，AI 绝不输入、不保管、不记录密码。
3. 装不完不硬闯：某项装不上时如实报告，评估"能不能先干不需要它的活"（如 MySQL 卡住可先聊需求/搭前端骨架），重新排期并写盘。
4. 检测/安装中遇到防坑清单没有的新坑：解决后追加到 pitfalls.md，并按 `../../references/experience-log.md` 记一条 pitfall 事件（代办安装另记 install 事件）。
