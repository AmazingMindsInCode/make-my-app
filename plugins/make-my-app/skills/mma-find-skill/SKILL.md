# 我要做软件 · 能力缺口雷达（mma-find-skill）

黄金路径覆盖不到的地方（小程序对接、专业 PDF 生成、地图、语音、特定平台 API……）不硬编凑合——**承认缺口、找到帮手、用户点头才装**。

## 一、什么算能力缺口（先自检，别滥用）

满足以下任一条才算：
- 子任务需要专业领域知识/官方 SDK 细节（如微信支付回调验签、百度地图坐标系），本地工具没有现成能力，硬写质量没保障；
- 需要反复调试的第三方集成，已有 skill/MCP 明确不支持；
- 用户主动点名的能力（"能不能加个 XX 地图"）超出黄金路径。

**不算**缺口（不要触发本技能）：普通 CRUD、页面样式、常规构建——这些是 mma-build 本职。

## 二、流程（五步）

1. **亮明缺口**（大白话）："接下来要做『地址地图选点』，这活需要专门的地图工具包，我手头没有现成的。我去帮你找找靠谱的现成方案，找到了给你挑。"
2. **检索**（用可用的搜索工具 WebSearch / WebFetch）：
   - **先查 `../../references/addons-registry.md`**：缺口若已在注册表登记（如页面美观、真机验证），直接转 mma-addons 走安装流程（经用户同意），不重复检索发明。
   - 检索方向：`site:github.com` 的 Claude/Agent skills 市场（如 awesome-claude-code-skills 类清单）、skill 市场站、官方 SDK 文档与示例仓库。
   - 候选必须能落到**可安装的实体**：一个 git 仓库 / 一个插件市场条目 / 一份官方文档+SDK。纯文章不算候选。
   - 每个候选查证：最近是否维护、安装方式、是否免费开源、和 Windows/Git Bash 环境兼容吗。
3. **出建议卡**（2-3 个候选，一次一问让用户选）：

```
🔧 帮手候选（用于：地图选点）
- A ⭐推荐：bmap-jsapi-gl skill（百度地图官方 API 封装）
    好处：官方 API、示例全、免费额度够用  代价：要注册拿一个免费钥匙
- B：高德地图 skill
    好处：文档中文友好  代价：同样要注册，且和我们页面风格要磨合
- C：不装帮手，改需求为"手填地址"
    好处：零依赖马上能做  代价：没有地图点选体验
👉 推荐 A。装哪个？
```

4. **经用户确认后安装**：
   - 安装目标：用户级 skill 目录 `~/.agents/skills/<skill-name>/`（git clone 或按该 skill 的安装说明；装完提醒用户可能需重启会话生效）。
   - **绝不在用户点头前下载/安装任何东西**；绝不安装闭源收费、要求付费订阅、来路不明（无 README/无维护）的候选——这类直接从建议卡剔除并说明。
   - 安装后做一次冒烟验证（该 skill 的最小用法跑通），把"新帮手已就位 + 用它干什么"记入 progress.json 的 decisions。
5. **继续原任务**：回到 mma-build 的任务循环，用新能力把活干完。

## 铁律

1. 建议卡必须含"不装、改需求"这个保底选项——很多缺口改需求比装工具更划算，要如实给这个选项。
2. 检索不到可靠候选时如实说"没找到靠谱的现成帮手"，给替代路线（改需求/降级实现/人工步骤），**不推荐不可靠的东西**；检索落空与安装失败都按 `../../references/experience-log.md` 记入经验日志（这正是插件该补能力的信号）。
3. 安装动作三要素：用户同意 → 来源可信 → 装完验证。缺一不可。
4. 涉及注册第三方平台/申请钥匙（AK/密钥）：申请动作由用户完成，你给逐步指引（wizard 精神：只有人能做的步骤交给人）。
5. 装与不装的决策记入 decisions，避免下次同样缺口重新纠结。
