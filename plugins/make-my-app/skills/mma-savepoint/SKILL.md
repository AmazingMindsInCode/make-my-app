# 我要做软件 · 存档点（mma-savepoint）

用户不需要知道 git 存在。他只知道三件事：**能存档、能看存档列表、能读档回滚**。

## 存档（说"存个档"就触发）

1. **入库前检查**（P14，铁闸）：
   - `.gitignore` 必须已覆盖：`node_modules/`、`target/`、`*.log`、`application-local.yml`、`.make-my-app/run/`、`.make-my-app/tests/last-run.json`。
   - `git status` 里若出现密码文件/超大文件/临时文件 → 先补 .gitignore 或删除，绝不带病入库。
   - **考卷记录**（搭好骨架之后才有）：确认 `.make-my-app/tests/last-run.json` 是最近一次改代码之后跑的，不是就先跑 `node .make-my-app/tests/run-tests.mjs --restart`（带 `--restart`，确保测的是最新代码）。结果写进存档名尾巴（`[存档] 完成了记账页面 · 考卷 12/12 过`）和 saves 记录的 `tests` 字段。没全过也照存（存档是安全垫，不是奖状），但存档名里如实写"有 N 条没过"。
2. 没有 `.git` → 静默 `git init`（不向用户提 git 这个词）。
3. 已有 `.git` 且是用户自己的仓库 → 尊重：不改动历史、不碰分支，只在当前分支追加提交；若有他人未提交的改动，先问用户"这些不是我做的改动，一起存进去吗？"
4. `git add -A` + `git commit`，提交消息用大白话任务名（格式：`[存档] 完成了记账页面`），时间自动记录。
5. progress.json 的 saves 数组加一行（msg + time），立即写盘。
6. 回用户一句大白话："已存档 ✅ 完成了记账页面"。**不展示任何 git 输出。**

## 看存档列表（/status 或用户问"存过哪些档"）

把 `git log --oneline -8` 翻译成大白话列表：

```
💾 你的存档点：
- 刚才      完成了统计图表
- 昨天 14:02 完成了记账页面
- 昨天 10:30 骨架搭好了
```

## 读档回滚（用户说"回到上个存档点/搞砸了想撤销"）

1. 先问清楚回到哪：默认推荐"上一个存档点"（👉 推荐）。
2. **安全垫**：回滚前先把当前状态自动存一个档（`[存档] 回滚前自动备份`）——这样反悔了还能再回来。
3. 执行回滚，然后把回滚后果用人话说明："刚才之后做的改动已经撤掉，软件回到『完成了记账页面』那会儿。"
   - **数据不跟着回滚**：读档回去的是代码和表结构迁移文件；库里已经记下的数据、后来加上的表和字段都还在。旧版照样能跑（迁移设置允许库比代码"新"，新字段按规矩都允许为空），要跟用户说清楚"你这段时间记的东西都还在"。
4. progress.json 同步修正（tasks 状态、stage 按存档内容回拨），立即写盘。
5. 回滚后主动建议："我带你在回到的版本上跑一圈，确认没问题。"（验证闭环精神）

## 铁律

1. 对用户的全部输出中**不出现 git/commit/branch 等词**，只用"存档、读档"。
2. 密码进存档 = 最高级事故，入库前检查不可跳过。
3. 回滚必先自动备份当下状态；绝不执行不可逆操作而没有退路。
4. 存档动作要快（这是高频操作，别借机长篇大论）。
