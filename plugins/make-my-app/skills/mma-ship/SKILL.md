# 我要做软件 · 三级上线（mma-ship）

原则：**上线是渐进的，不是一跳到公网**。每一级：说清目标 → 确认用户真想去 → 分步做（只有用户能做的步骤交给人做）→ 真实验证 → 庆祝一句，并告诉他"停在这级也完全能用"。

## 沟通规范

- 每级开始先讲人话版目标："第二级就是让和你连同一个 WiFi 的手机也能打开你的软件。"
- 涉及花钱（L3 买服务器/域名）和开门（防火墙）的动作，**必须用户亲口确认**后才继续。
- 安全事项用后果说话："公网上线后如果数据库密码太简单，就像把家门钥匙插在门上。"

## L1 本机（自己的电脑自己用）

1. 出成品：`cd frontend && npm run build`（前端成品进后端包裹）→ `cd backend && mvnw.cmd -s .mvn\aliyun-settings.xml package -DskipTests`。
2. 让用户**双击 start.bat**（不许你代跑——这是用户的"开机仪式"），浏览器自动打开。
3. 验证：用户亲手点开核心功能走一遍；你用 curl 抽查健康接口。
4. 存档点："L1 本机版上线"。progress.json 的 shipLevel=1。

## L2 局域网（同 WiFi 的设备能访问）

1. 前置确认（一次一问）："想给谁用？他们的手机/电脑和你的电脑连的是不是同一个 WiFi？"（👉 适合：家人/小团队）
2. 你做：`ipconfig` 查本机 IP（教用户认 IPv4 那行）。
3. 用户做（门卫登记，给截图级步骤）：Windows 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → 8080 → 允许。
4. 验证：用户拿手机浏览器开 `http://<IP>:8080`，亲眼看到页面（**必须真机验证**，这是 L2 的过关凭证）。
5. 提醒两句：电脑睡眠/关机别人就访问不了；软件数据还在你这台电脑上。
6. 存档点 + shipLevel=2。

## L3 公网（全世界都能访问）

**先过三道确认门**（全过才开工，任何一道犹豫就建议先停在 L2）：

- 门 1（花钱）：需要租一台云上电脑。给出建议（阿里云/腾讯云**轻量应用服务器**，2 核 2G 起步，约几十元/月，新用户有优惠）——买哪家的决定权在用户。
- 门 2（安全）：公网上线前必须改掉 MySQL 弱密码（后果说法见沟通规范），数据库绝不开公网端口。
- 门 3（专人）：服务器登录密码/密钥由用户保管，你只引导不保管。

然后分步（每步做完验证再做下一步）：

1. 用户买好服务器，告诉你系统选了什么（👉 推荐：Ubuntu 22.04 或 Windows Server，用户熟 Windows 就选 Windows）。
2. 网络：教用户在云控制台"防火墙/安全组"放行 8080（和远程登录端口）——云上的门卫，截图级指引。
3. 装 JDK17 到服务器（你给命令，Windows 服务器可远程桌面装；Linux 给逐条命令）。
4. 数据搬运：在服务器上装 MySQL、建库、把本机数据导出导入（你生成导出/导入命令，账号密码用户自己输）。
5. 部署：把 `app.jar` 和启动脚本传上去，后台方式跑起来（Linux 用 systemd，Windows 用任务计划/nssm——给现成配置文件）。
6. 验证：用户用自己的手机（关掉 WiFi 用流量）访问 `http://服务器公网IP:8080`，走一遍核心功能——**流量访问成功才算 L3 过关**。
7. 可选加装（分别确认）：域名（好记的门牌）→ nginx（接待员）→ HTTPS（带锁的通道）。每项给出要不要的判断建议（👉 HTTPS：有用户输入信息的必须上；纯自己看看可以缓）。
8. 存档点 "L3 公网上线" + shipLevel=3 + done 阶段收尾（项目 README 更新为含服务器信息的版本，密码位置写"在服务器上，见你的密码本"）。

## 铁律

1. 每级必须真机验证通过才标完成；用户说"应该可以了"不行，要他亲手打开过。
2. 花钱、开门、给密码三类动作永远用户亲自做。
3. 任何一级卡住：如实报告 + 评估"停在前一级先用着"，不硬推。
4. L3 上线后主动提醒数据备份："云电脑也可能坏，每月导一份数据到你自己的电脑"——并给一条傻瓜备份命令。
